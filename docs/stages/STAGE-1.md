# Что должно быть сделано

Получить рабочее решение, воспроизводимое без специальной настройки в любом окружении. Единственная внешняя зависимость - Docker.
Любой человек, склонировав репозиторий, должен одной командой поднять весь стек и увидеть работающее приложение: UI, API, БД, начальная аутентификация.
Все необходимые настройки и конфигурации должны быть в репозитории.

### 1. Git-репозиторий

* базовая структура файлов
* настройка .gitignore
* размещение на GitHub

### 2. Docker compose

- `docker compose up` из корня репозитория поднимает:
  - `postgres` — с инициализацией схемы через `init.sql`;
  - `keycloak` — с импортом `realm-export.json`;
  - `backend` — NestJS, подключённый к Postgres и Keycloak;
  - `frontend` — собранный Vite + отданный через nginx.
- Все сервисы видят друг друга по именам внутри docker-сети.
- Фронт доступен на `http://localhost:9000`, бэк — на `:9100`, Keycloak — на `:9200`, Postgres — на `:9300`.
- Минимум ручной настройки после запуска.
- Настройки Postgres и Keycloak монтируются из папок. `init.sql` проверяет, что есть схемы, необходимые для работы бэкенда и Keycloak. `realm-export.json` задает клиенты для подключений от бэкенда и от фронтенда, а так же определяет роли и пользователей по умолчанию.

### 2. Фронтенд: каркас

Vite + React + TypeScript. Базовое приложение с минимальной настройкой. Несколько базовых роутов: стартовая страница-лендинг, аутентификация, защищенный роут для работы.
Работа с Keycloak через библиотеку `keycloak-js` или аналог. При переходе на роут `/auth` должно вызываться перенаправление на Keycloak для аутентификации. После - возврат на корневой роут. Плюсом будет использование общего контекста для данных о пользователе.
Nginx это сервер статики и нужен, чтобы отдавать файлы по запросу, является общепринятым способом упаковки клиента в Docker.

### 3. Бэкенд

NestJS, базовое приложение с минимальной настройкой. Запускается, работает. Плюсом будет настроенное подключение к Postgres.
