# Клиент забирает весь список заявок

`useApplications` вызывает `GET /applications` без ограничения размера и кладёт в список весь ответ. Тот же запрос повторяется целиком примерно раз в 15 секунд, а также сразу после смены фильтра и поиска.

Поиск входит в зависимости запроса без паузы после ввода. Каждый символ заново грузит список.

Фильтры главной лежат в `useState` у `App`. Обновление страницы их сбрасывает. Ссылку на конкретную выборку отправить нельзя.

# Чат на странице заявки запрашивается дважды

`ApplicationPage` вызывает `useChatItems`, чтобы узнать число сообщений и пометить уведомления прочитанными. `Chat` вызывает тот же хук для ленты. Два опроса одного адреса идут примерно раз в пять секунд.

# Ошибка загрузки выглядит как пустой экран

Пока заявка грузится, `ApplicationPage` возвращает `null`. Экран пустой.

Если запрос упал не с 404, хук пишет текст в `error`. Страница `error` не читает и показывает «Заявка не найдена».

`AccountPage` без пользователя делает `return` без элемента. Гость на `/account` видит пустой рендер.

Список своих заявок сервер уже отдаёт по `mine`. Страница ещё раз фильтрует его по `authorId`.

# Таблица переходов скопирована с бэкенда

Кнопки смены статуса читают `domain/statuses.ts`. Та же таблица есть на сервере. Если копии разойдутся, клиент покажет действие, а сервер ответит отказом.

# Страницы сами решают, пускать ли гостя

Список, карточка заявки и чат не требуют входа. Отдельной защиты маршрута нет. Каждая страница сама решает, показать ли форму входа.
