# Список заявок без ограничения

`GET /applications` возвращает все подходящие строки. Параметра страницы или курсора нет. Фильтр, поиск и сортировка проходят по всей выборке.

Сортировка `activity` для каждой заявки считает подзапрос последнего сообщения. Отдельным запросом считается статистика сообщений. Фронт повторяет весь этот запрос по таймеру.

# Смена статуса без блокировки строки

`allowedTransitions` проверяет переход после чтения строки. Запись идёт отдельным `UPDATE`.

Два одновременных запроса видят один исходный статус. Оба проходят проверку и оба пишут событие в ленту. В заявке остаётся статус того запроса, который записал последним. В ленте остаются переходы, которых в таблице статусов не было.

# Схема базы не зафиксирована

`init.sql` создаёт схемы `app` и `keycloak`. Таблицы создаёт TypeORM из entity. В `AppModule` включён `synchronize`, пока `DB_SYNCHRONIZE` не равен `false`. В Compose он равен `true`. Миграций нет.

При следующем изменении поля TypeORM сам меняет уже заполненную базу на старте. Истории схемы нет, откатить изменение нечем.

# Админ узнает о заявке только после первого входа

Получателей уведомлений сервис берёт из таблицы пользователей. `UsersService.touch` создаёт строку при успешной проверке токена. Администратор, который ещё не вызывал API, в таблице отсутствует, и `application_created` ему не уходит.

# Заявки, чат и файлы читаются без токена

Список, карточка, лента чата и скачивание вложения открыты без авторизации. Писать и менять статус может автор или администратор.

Любой, кто знает адрес, читает чужую переписку и вложения.
